# Ballot prompts

Prompts for researching what is on a voter's ballot: which elections are coming up, where the
official sample ballot lives, who the candidates are, and what each contest or ballot question
means. The goal is a neutral, source-backed picture of the ballot, not a recommendation.

## How these prompts are delivered

This domain uses both delivery types:

- **`external-chat`** prompts (contest, question, and candidate research, plus the candidate roster)
  are copied by the voter into their own AI chat. Each ends with a paste-back contract so the
  answer can be imported into Symthink's ballot research tree.
- **`symthink-api`** prompts (source discovery, upcoming elections) are sent by Symthink's server to
  a model with web search, and the server parses the JSON reply.

Import the first group from `@symthink/prompts/external-chat` and the second from
`@symthink/prompts/symthink-api`.

## Prompt details

### candidate-research

Researches one candidate on the user's imported ballot using public record, campaign site, filings, endorsements, and prior office experience.

- **Id:** `ballot.candidate-research`
- **Template:** [`prompt.md`](./candidate-research/prompt.md) · [`meta.json`](./candidate-research/meta.json)
- **Output:** `single` (returns one string)
- **Paste-back into Symthink:** yes
- **Wired in Symthink from this package:** not yet
- **Symthink source:** `symthink-io/src/utils/ballotAiResearchContext.helpers.ts (buildBallotCandidateResearchPrompt)`
- **Symthink docs:** `symthink-io/docs/developer-guide/systems/ballot-research.md`

| Variable | Type | Required | Description |
|----------|------|----------|-------------|
| `electionName` | `string` | yes | Election display text. |
| `electionDay` | `string` | no | Election date, ISO `YYYY-MM-DD` preferred. |
| `contestTitle` | `string` | no | Title of the contest the candidate is running in. |
| `candidateName` | `string` | yes | Candidate name without the `Candidate:` prefix. |
| `fecCandidateId` | `string` | no | Federal Election Commission candidate id; adds an FEC profile link. |

### candidate-roster

Fills in verified candidate names (and any missing ballot-question titles) for every contest parsed from a sample ballot, as a single paste-back tree.

- **Id:** `ballot.candidate-roster`
- **Template:** [`prompt.md`](./candidate-roster/prompt.md) · [`meta.json`](./candidate-roster/meta.json)
- **Output:** `single` (returns one string)
- **Paste-back into Symthink:** yes
- **Wired in Symthink from this package:** not yet
- **Symthink source:** `symthink-io/src/utils/ballotCandidateRoster.helpers.ts (buildBallotCandidateRosterPrompt)`
- **Symthink docs:** `symthink-io/docs/developer-guide/systems/ballot-research.md`
- **Notes:** Uses its own roster-specific paste-back contract instead of the shared partial. A blank line now follows every election block; the symthink-io source omits it after the last election.

| Variable | Type | Required | Description |
|----------|------|----------|-------------|
| `elections` | `Election[]` | yes | One entry per imported election: `name`, optional `electionDay`, `ballotStyle`, `partyContext`, plus `contests[]` and `questions[]` with `displayText` and optional `votingInstruction`. |
| `officialSourceUrl` | `string (URL)` | no | Official sample-ballot page the parse came from. |

### source-discovery

Web-search prompt that finds official sample-ballot or voter-lookup pages for the voter's jurisdiction and returns ranked sources as JSON.

- **Id:** `ballot.source-discovery`
- **Template:** [`prompt.md`](./source-discovery/prompt.md) · [`meta.json`](./source-discovery/meta.json)
- **Output:** `single` (returns one string)
- **Paste-back into Symthink:** no
- **Wired in Symthink from this package:** not yet
- **Symthink source:** `symthink-io/supabase/functions/_shared/services/ballot-source-discovery.ts (buildDiscoveryPrompt)`, `symthink-io/supabase/functions/_shared/services/ballot-civic-context.ts (formatCivicJurisdictionPromptBlock)`, `symthink-io/supabase/functions/_shared/services/ballot-civic.service.ts (formatCivicElectionsForPrompt)`
- **Symthink docs:** `symthink-io/docs/developer-guide/systems/ballot-research.md`
- **Notes:** Sent to the OpenAI Responses API with web search. Blank lines between the jurisdiction, elections, and saved-context blocks are now consistent.

| Variable | Type | Required | Description |
|----------|------|----------|-------------|
| `location` | `string` | yes | Human-readable location label (e.g. `Montgomery County, Maryland`). |
| `districts` | `{ type, name }[]` | no | Districts that cover the voter (congressional, legislative, …). |
| `civicElections` | `{ name, electionDay? }[]` | no | Upcoming elections from Google Civic, context only. At most 6 are included. |
| `savedContext` | `SavedBallotContext` | no | Previously confirmed, non-sensitive ballot context (reuse scope, key, precinct, ballot style, party, verified source). Pass only when it is fresh or a low-confidence source. |

### upcoming-elections

Web-search prompt that lists the next upcoming election events (one row per event, party primaries split) for the voter's jurisdiction as JSON.

- **Id:** `ballot.upcoming-elections`
- **Template:** [`prompt.md`](./upcoming-elections/prompt.md) · [`meta.json`](./upcoming-elections/meta.json)
- **Output:** `single` (returns one string)
- **Paste-back into Symthink:** no
- **Wired in Symthink from this package:** not yet
- **Symthink source:** `symthink-io/supabase/functions/_shared/services/upcoming-elections-discovery.ts (buildUpcomingElectionsPrompt)`
- **Notes:** Sent to the OpenAI Responses API with web search. Same wording as symthink-io; blank lines around the jurisdiction and Google Civic elections blocks are now consistent (symthink-io omits some of them).

| Variable | Type | Required | Description |
|----------|------|----------|-------------|
| `location` | `string` | yes | Human-readable location label. |
| `districts` | `{ type, name }[]` | no | Districts that cover the voter. |
| `civicElections` | `{ name, electionDay? }[]` | no | Upcoming elections from Google Civic, context only. At most 6 are included. |
| `state` | `string` | no | Voter's state name; defaults to "the voter's state" in naming rules. |
| `todayIso` | `string (YYYY-MM-DD)` | yes | Reference date; only elections strictly after it are returned. |
| `todayLabel` | `string` | yes | Reference date in long form (e.g. `Saturday, October 24, 2026`). |
| `topElectionCount` | `number` | no | How many upcoming events to return before adding the next presidential election. Default 3. |
